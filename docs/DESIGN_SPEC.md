# あいうえおゲーム 設計仕様書（現状分析）

## 1. 文書の位置づけ

この仕様書は、現行の `index.html`・`script.js`・`styles.css` と同梱データ、および2026-09-29に確認したゲームルールを元にしています。ルールとして決定済みの振る舞いと、コード上まだ未実装の機能を分けて記載しています。

## 3. 現行画面

上から次の要素を配置します。

1. お題欄と編集・更新アイコン
2. プレイヤー人数選択（2〜8人）
3. 5行×10列の50音表と選択文字の確定ボタン
4. 人数に応じて生成するプレイヤーカード
5. 新規ゲームボタン

プレイヤーカードにはアイコン、名前、名前編集アイコン、ワード入力欄、確定ボタンを表示します。HTMLにはプレイヤー人数の初期選択値が指定されていないため、先頭の2人が初期値になります。

## 4. 状態とデータ

- お題候補はJavaScript内の固定配列5件です。CSVは未接続です。
- 人数はセレクトボックスの値として保持し、人数変更時にプレイヤーカードを再生成します。
- 現在選択中の文字セルは `selectedCell` 1件で管理します。
- 確定済みセルは `confirmed` クラスを付け、以後クリックできない状態にします。
- プレイヤー名とワードはDOM内に保持します。サーバー通信、データベース、LocalStorageへの保存はありません。
- ワード確定後は入力欄を隠し、固定長の伏せ字を追加します。入力したワードを使った正誤判定はありません。
- 正式ルールでは、正規化済みワード、開放済み音、生存者一覧、ランダムに決めた初手、現在の手番を状態として持つ必要があります。現行コードにはまだありません。

## 5. 正式ルールに基づく処理フロー

1. セットアップでお題、参加人数、各プレイヤーの秘密ワードを登録します。
2. 全ワードを伏せ字で表示し、ゲームを開始します。
3. 初手プレイヤーをランダムに決めます。以後の手番順はプレイヤーID昇順の循環で、脱落者は飛ばします。
4. 手番開始時に終了条件を確認します。生存者が1人ならその人が1位となり、終了します。
5. 生存者全員の未公開文字が同じ1種類の音だけなら、ゲームを終了し、生存者全員を同率1位とします。
6. 終了条件に該当しない場合、手番プレイヤーは未開放の音を1つ選びます。該当文字がなくてもその音は使用済みにします。
7. 選ばれた音と一致する伏せ字を、全プレイヤーのワード上で同時に文字表記へ切り替えます。同一ワード内に複数あれば全箇所を開放します。
8. 全文字が公開されたプレイヤーを脱落させます。同じ音の開放で複数人が同時に脱落した場合、その全員を同率1位とします。
9. 脱落後に終了条件を確認し、終了しなければ次の生存者へ手番を渡して4へ戻ります。

## 6. 現行コードの処理フロー

### 初期表示

`DOMContentLoaded` 後、50音表を生成し、現在の人数分のプレイヤーカードを生成します。

### お題更新

更新アイコンのクリックで、JavaScript内の候補から1件をランダムに選んで表示します。編集アイコンはHTMLにありますが、現行コードではイベント処理がありません。

### 文字選択

未確定セルをクリックすると、そのセルに `selected` クラスを付け、全体の確定ボタンを有効化します。確定操作で `confirmed` クラスを付け、セルを灰色にします。同じセルは再選択できません。

### プレイヤー入力

人数変更時にプレイヤーカードを作り直します。名前編集は `prompt` で受け付け、ワード確定は空欄でないことのみを確認します。ワードの正規化は入力中に行います。

## 7. 版の整理

- `index.html` と `script.js` が現在の画面・処理に対応します。
- `index1.html` は `script1.js` を読み込みますが、`script1.js` は空です。単独では動作しません。
- `old/` は別構成の試作です。お題入力、提出文字欄、ワード表示切替など異なるUI・関数を持ちます。現行版と混ぜないでください。
- `odai.csv` は現行版で使用されていないため、お題を増やす場合は読み込み処理の追加が必要です。

## 8. 再開時の実装課題

### 優先度高

- 1〜7文字を受け付け、8文字以上はエラー通知して登録を拒否する。現行は8文字まで切り詰め、伏せ字も常に8個のため仕様に合わせて修正する。
- 濁音・半濁音を清音へ、小書きの「っ」「ゃ」「ゅ」「ょ」を大きい文字へ正規化し、正規化後の文字で照合する。「ー」は変換せず独立した1音として扱う。
- ランダムな初手、生存者のみのID昇順循環、1手番1音、該当なしでも使用済みにする処理を実装する。
- 選択音の全プレイヤー一斉公開、全文字公開時の脱落、同時脱落者の同率1位、特殊終了条件の判定を実装する。
- 「New Game」ボタンに処理を追加し、お題・選択済みセル・プレイヤー入力を初期化する。
- 「お題編集」ボタンを実装するか、未使用なら画面から外す。

### 優先度中

- `odai.csv` を正式なお題データとして読み込むか、固定配列を唯一のデータ源にするか決める。
- 文字盤を1文字ずつ操作できるボタンとして実装し、キーボード操作・フォーカス状態・読み上げラベルを整える。
- プレイヤーのワードを画面に表示する場合のプライバシー／覗き見対策と、編集・再入力の流れを定義する。

## 9. 現時点の非対応

生存者間の手番管理、選択文字による伏せ字公開、脱落判定、終了判定、順位表示、ラウンド管理、ゲーム状態の保存・共有は実装されていません。現段階では、文字を選んで使用済みにするところまでのUI試作です。
